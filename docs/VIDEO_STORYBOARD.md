# Demo storyboard

Production direction: a calm fintech explainer intercut with genuine moving application footage and public blockchain evidence. 1920×1080, 30fps, target 150 seconds, maximum strictly below 180 seconds. Apply the existing pine/Manrope/branching identity. No third-party music, fabricated wallet popup or screenshot-based fake walkthrough.

| Time | Picture | Claim / evidence |
| --- | --- | --- |
| 0–12s | Original brand animation; one amount branches into three labeled rails | Conceptual allocation, explicitly illustrative |
| 12–36s | Real moving wallet/setup/rules application recording | Owner setup and allocation editing; only use completed, recorded actions |
| 36–58s | Real Receive workflow, supported token/address and test-payment transaction states | A regular ERC-20 transfer; distinguish submission from confirmation |
| 58–82s | Original architecture motion graphic | Token Transfer → Reactive Omni → authenticated callback; diagram labeled explanatory |
| 82–110s | Moving receipt expansion, actual destinations and transfers | Real on-chain outcomes; do not insert fake success timing |
| 110–134s | Moving Proof page and public transaction references | Original M1 origin/Reactive/callback/replay evidence; measured two-second observation properly qualified |
| 134–150s | Brand close and honest testnet/security limits | Open source, independent review needed before mainnet; no tax-liability claim |

Footage must be recorded from the functioning application. Any locally automated EIP-1193 test wallet is named as such and signs through the encrypted Node/Foundry keystore; no private key is injected into a page and no third-party wallet UI is impersonated. Long network waits may be cut; transaction outcomes must remain authentic. Retain original recordings and the edit timing map.
